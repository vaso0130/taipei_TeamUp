# 設計規格：入口頁彩蛋「湊隊」

狀態：實作中（2026-09-10）。位置：`/` 的路網板（`HeroMap.vue`）。對應 ADR-035 A 的入口頁；彩蛋慣例沿用 ADR-032（深色模式整人、圓標連點）。

## 一句話

路網板上的點本來就是「等著被組隊的人」。彩蛋讓訪客親手把他們連成隊：底層是**拉線**手感，上面疊一個有節奏的**湊隊**小遊戲。整段在同一張 canvas 上發生，不開新頁、不擋 CTA。

## 觸發與退出

- **進入**：在路網板的空白處（不是文案、不是 CTA）**連點三下**（600ms 內），或鍵盤在板上按 `G`。進入時文案區淡到 35% 並停止 LED 掃亮，板子右上角出現小面板（見「HUD」）。
- **退出**：`Esc`、面板的「離開」、或 30 秒無互動自動淡出回展示模式。退出時文案回復、正在自動生成的路線繼續。
- **不啟用**：`prefers-reduced-motion: reduce`（維持靜態圖）；寬度 < 360px（太小玩不了，仍可拉線但不進遊戲）。
- 觸控裝置：三連點改為**長按 600ms**；拉線用單指拖曳。
- 進入後展示模式的自動生成路線暫停（`spawnIn` 凍結），避免搶點。

## 底層：拉線（永遠可用，不需進遊戲）

- 指標移到點附近 14px 內，該點放大成空心圓標並顯示「抓取」游標（`cursor: grab`）。
- 按下並拖曳：從該點拉出一條與目前指標位置相連的線（線色＝目前遊戲色，展示模式為白色 60%），沿途經過的點會被「吸附」加入路線（進入 14px 內即接上，最多 5 站），每吸附一站播放圓標脈動一次。
- 放手：若路線 ≥ 2 站，畫成完整路線（45°/90° 折線與端點圓標）停留 1.8 秒後淡出；若只有 1 站，什麼都不發生。
- 拖曳期間該路線上的點停止漂移（讓手感穩定），放手後恢復。
- 在展示模式拉線不計分，只是好玩；同時最多 1 條使用者路線 + 3 條自動路線。

## 遊戲：湊隊

**目標**：限時內把「同色閃爍」的人依序連成一隊。

### 一局流程

1. 系統挑 N 個彼此不會太遠的點（N 由目前活動設定決定，見「與活動設定的關係」），依序給編號，讓它們以本局線色**同步閃爍**（外圈亮環 0.8s 週期），編號 1 的點多一個外圈標示「起點」。
2. 玩家從起點開始拉線，依序吸附到 2、3、…、N。吸到正確的下一站：該站變實心圓標、發出短促脈動；吸到錯誤的站或非目標點：線段閃紅 200ms 並被彈開（不中斷路線，只是不接上）。
3. 全部接完 → **成隊**：整條路線亮成該色、兩端圓標脈動、板中央短暫浮出「成隊！」與本局時間；1.2 秒後路線淡出，下一局開始（N 可能 +1，見難度）。
4. 倒數歸零仍未完成 → 目標點停止閃爍、路線淡出、HUD 顯示「差一點」，連續成隊數歸零；下一局開始。
5. 玩家放手（拖曳中斷）不算失敗，可以從**最後一個已接上的站**重新拉；起點永遠可重抓。

### 難度與節奏（全部是常數，集中在檔頭，不散落）

| 參數 | 值 |
|---|---|
| 首局站數 | 活動 `minMembers`（無活動資料時 4） |
| 站數上限 | 活動 `maxMembers`（無活動資料時 5），連續成隊 2 局後 +1，達上限維持 |
| 每局時限 | `6s + 1.5s × 站數`，連續成隊每 2 局 −0.5s，下限 `4s + 1s × 站數` |
| 目標點分布 | 從一個隨機種子點出發的最近鄰鏈（重用 `pickRoute`），再打亂順序但確保相鄰站距離 ≥ 60px |
| 吸附半徑 | 14px（觸控 22px） |
| 同時線路 | 遊戲中只有玩家 1 條 |

### 計分（只在本次瀏覽器 session 記錄，`sessionStorage`，不上傳）

- 每局成隊得 `站數 × 10`，剩餘秒數每秒 +2（四捨五入）。
- 連續成隊 streak：第 3 局起每局額外 +10。
- HUD 顯示：本局倒數、目前分數、連續成隊、本次最佳。
- 不需要帳號、不寫任何 API、不寫 localStorage（避免跨 session 累積被當成「進度」）。

### 與活動設定的關係（最高原則：不寫死活動規則）

- 進入遊戲時讀 event store 的 `summaries`／`details`：若有 open 活動（依 `/events` 同一套排序取第一場），用它的 `minMembers`／`maxMembers`／`termTeam`／`termMember`；成隊文案為「成{termTeam}！」、HUD 副標「把 N 位{termMember}連起來」。
- 成隊 3 次以上，目標點旁會以小字浮現該活動**啟用角色**的名稱（`roles` 依 `sortOrder`，循環取用）作為裝飾，讓玩家不經意看到這場活動在找什麼人。沒有活動資料就不顯示。
- 完全沒有活動資料時用預設 4／5 與「隊伍／成員」（這是 seed 預設值，不是黑客松規則）。

## HUD（右上角小面板）

- 寬 220px（手機全寬置頂），半透明 ink 底 `rgba(22,48,43,.85)`＋1px 白 8% 邊，文字沿用 hero 的 `--board-fg`／`--board-dim`／`--board-led`。
- 內容：第一行「湊隊」＋「離開」按鈕（44px）；第二行倒數（等寬字，剩 2 秒內變琥珀）；第三行「分數 120・連續 3・最佳 260」；第四行提示文字（首局：「按住起點，依序拉到閃爍的人」；成隊後：「成{termTeam}！+50」；失敗後：「差一點，再來一局」）。
- `role="status"` 的視覺隱藏區播報成隊／失敗（不播報倒數，避免讀屏吵）。
- 進入遊戲時焦點移到「離開」按鈃所在面板（`tabindex=-1`），`Esc` 由面板監聽。

## 無障礙與邊界

- 遊戲是彩蛋，不是達成任何任務的必要路徑；CTA 與所有鍵盤流程不受影響。
- `pointer-events`：canvas 只在遊戏中或指標靠近點時攔截；文案與 CTA 永遠在 canvas 之上可點。
- 鍵盤：`G` 進入、`Esc` 退出；遊戲本身需要指標（拉線），面板提示會說明「需要滑鼠或觸控」。
- 減少動態：不進遊戲、不拉線（保持原本靜態圖）。
- 效能：只在遊戲中增加 hit-test（每幀 O(n)，n ≤ 70），不影響展示模式。
- 深色／淺色主題：板子固定深色，不受影響。

## 實作邊界

- 全部在 `apps/web/src/components/landing/`：`HeroMap.vue` 抽出「世界」（節點、路線、繪製）到 `hero-world.ts`（純 TS，可單元測試），新增 `hero-game.ts`（遊戲狀態機，純 TS）與 `GameHud.vue`；`HeroMap.vue` 負責 canvas、事件與把兩者接起來。
- 不引入套件；不改 `main.css` 既有規則；不碰 router／store（只讀 event store）。
- `LandingPage.vue` 需把 `HeroCopy` 包在可淡出的容器並接收 `gameActive` 狀態。

## 驗收

- [ ] 桌機：三連點進入、Esc 退出、30 秒閒置自動退出；文案淡出／回復。
- [ ] 拉線在展示模式可用、放手成線、1.8 秒淡出；不影響自動路線。
- [ ] 一局可完成：正確順序吸附、錯站彈開、成隊文案、分數與 streak 正確、難度遞增到上限。
- [ ] 讀書會為第一場 open 活動時，站數用 3→6、文案為「成讀書會！」、成隊 3 次後出現角色名。
- [ ] 375px 觸控：長按進入、單指拖曳、吸附半徑 22px；HUD 全寬置頂不遮文案。
- [ ] reduced-motion：三連點無效、無拉線。
- [ ] `pnpm lint`／`typecheck`／`build`；`hero-game.ts` 有單元測試（狀態轉移、計分、時限公式、活動參數注入）。
