# 個資最小化設計說明

本文件說明平台的個資設計原則與實作。原則只有一句：**不收就不會外洩。**

對外的隱私權政策文字在 `apps/web/src/pages/PrivacyPage.vue`（生效日期 2026-09-09）；本文件是其工程對照，兩者需同步修改。

## 收什麼、不收什麼

| 收 | 不收 |
|---|---|
| Email（登入用，唯一必要識別；應用層加密儲存） | 真實姓名 |
| 暱稱（自訂，不驗證；寫入時行內審查） | 電話 |
| 技能標籤、角色偏好（固定字典，非自由輸入） | 生日（只存「是否滿 18」布林值） |
| 自訂技能標籤（活動可開放少量自由文字，與自介同一審核單位） | 學校／公司／職稱 |
| 自我介紹（自由文字，發布前過審） | 身分證字號、住址 |
| 是否年滿 18（布林） | 頭像上傳（用種子產生的識別圖案代替） |
| | IP 位址（只留在 Cloud Logging，30 天輪替，不進應用資料庫） |

聯絡方式一律走站內訊息；個人頁面不提供任何外部聯絡欄位。

## Email 的儲存方式

1. 先正規化為 **canonical 形式**（ADR-028）：trim、小寫、去掉 `+tag`；gmail.com／googlemail.com 額外去掉 local part 的點並統一為 gmail.com。因此 **Gmail 別名視為同一帳號**（`a.b+x@googlemail.com` 與 `ab@gmail.com` 是同一人），無法用別名繞過「一人一隊」或停權。
2. 明文 email **不落地**。寫入前在應用層做 envelope encryption（存的是 canonical 形式）：
   - 每筆資料隨機產生 DEK（AES-256-GCM）
   - DEK 由 Cloud KMS 的 KEK 加密後，與密文一起存
3. 查重與登入比對用 `email_lookup = HMAC-SHA256(canonical(email), pepper)`，pepper 只存在 Secret Manager，不進資料庫；支援 pepper 輪替（舊 pepper 過渡期比對後改寫）。
4. 結果：直接撈走整份資料庫也無法還原任何 email。

## 未成年使用者

- 註冊只問一題：「你是否年滿 18 歲？」（僅在活動設定 `requires_adult_check` 時詢問）。
- 未滿 18 → 介面明確告知：法定代理人書面同意書**由活動主辦單位收取**，本平台不收也不存。
- 平台只存兩個布林值：`is_adult`、`guardian_consent_confirmed`（使用者自行勾選）。
- 活動要求年齡確認時，未回答者不能開團、申請、被邀請或被接受（ADR-026）。
- 不提供同意書上傳功能——那是含未成年人與監護人個資的高風險文件，平台沒有理由持有。

## 利用地區

- 主要資料（資料庫、密鑰、日誌）位於 Google Cloud `asia-east1`（臺灣）。
- 自動化內容檢測使用 Vertex AI **global 端點**（ADR-015：區域端點已無 Gemini 服務）；送檢 payload 只含內容文字與規則特徵種類，不含帳號識別資訊，因此跨區處理的是去識別化內容。專案層關閉 prompt 記錄與資料改善用途。

## 內容審核與隱私

- 所有使用者產生的文字發布前經過自動化風險檢測（已寫入隱私權政策告知）。
- 送往 Vertex AI 的 payload 只含內容文字與規則特徵的種類（kind），**不含 user id、email 或任何識別資訊**。
- 審核紀錄（`moderation_records`）不存原文，只存判定結果與內容的 SHA-256 hash；由每日排程在 **180 天**後清除（ADR-025 落實原本只寫在政策裡的承諾）。
- 中高風險、被檢舉、或帶風險訊號的內容及其對話脈絡由管理人員人工檢視；每次閱覽先寫稽核紀錄、寫不進就不給內容（fail-closed，ADR-030）。無風險訊號的一般對話**技術上**也不開放管理員調閱。
- 管理人員另可檢視**檢舉紀錄**（ADR-034）：檢舉原因、狀態、複審判定與雙方暱稱等中繼資料，**不含被檢舉內容、不含 Email**；此讀取不解密任何欄位。

## 保存期限

| 資料 | 期限 |
|---|---|
| 帳號刪除 | 立即軟刪（頁面消失、內容隱藏）→ 30 天後硬刪。**刪除後以同一 Email 再登入會建立全新帳號**，原資料不復原（ADR-029） |
| 活動資料（隊伍、申請、訊息） | 活動結束後依 `events.retention_days` 清除（預設 90 天，Cloud Scheduler 排程） |
| 審核紀錄 | 去識別化後 180 天（排程清除） |
| 稽核紀錄（audit_logs） | 180 天（排程清除） |
| Cloud Logging（含 IP） | 30 天輪替 |

## 當事人權利（個資法第 3 條）

- 個人資料頁一鍵匯出（JSON）：含帳號、各活動參加資料、隊伍、申請、訊息、本人內容的審核判定（只揭露自動／人工，不揭露審核者）、本人送出的檢舉、帳號狀態；被封鎖的內容不包含在內。每日 3 次。
- 一鍵刪除帳號（流程中明確說明會退出目前隊伍；發起人自動交棒）
- 蒐集告知（個資法第 8 條）直接呈現在註冊頁，不只藏在隱私權政策連結裡
- 聯絡管道：GitHub Issues（一般請求與申訴）、`SECURITY.md`（資安通報）——與隱私權政策頁一致
