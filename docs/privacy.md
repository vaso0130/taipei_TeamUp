# 個資最小化設計說明

本文件說明平台的個資設計原則與實作。原則只有一句：**不收就不會外洩。**

## 收什麼、不收什麼

| 收 | 不收 |
|---|---|
| Email（登入用，唯一必要識別；應用層加密儲存） | 真實姓名 |
| 暱稱（自訂，不驗證） | 電話 |
| 技能標籤、角色偏好（固定字典，非自由輸入） | 生日（只存「是否滿 18」布林值） |
| 自我介紹（自由文字，發布前過審） | 學校／公司／職稱 |
| 是否年滿 18（布林） | 身分證字號、住址 |
| | 頭像上傳（用種子產生的識別圖案代替） |
| | IP 位址（只留在 Cloud Logging，30 天輪替，不進應用資料庫） |

聯絡方式一律走站內訊息；個人頁面不提供任何外部聯絡欄位。

## Email 的儲存方式

1. 明文 email **不落地**。寫入前在應用層做 envelope encryption：
   - 每筆資料隨機產生 DEK（AES-256-GCM）
   - DEK 由 Cloud KMS 的 KEK 加密後，與密文一起存
2. 查重與登入比對用 `email_lookup = HMAC-SHA256(normalize(email), pepper)`，pepper 只存在 Secret Manager，不進資料庫。
3. 結果：直接撈走整份資料庫也無法還原任何 email。

## 未成年使用者

- 註冊只問一題：「你是否年滿 18 歲？」
- 未滿 18 → 介面明確告知：法定代理人書面同意書**由活動主辦單位收取**，本平台不收也不存。
- 平台只存兩個布林值：`is_adult`、`guardian_consent_confirmed`（使用者自行勾選）。
- 不提供同意書上傳功能——那是含未成年人與監護人個資的高風險文件，平台沒有理由持有。

## 內容審核與隱私

- 所有使用者產生的文字發布前經過自動化風險檢測（已寫入隱私權政策告知）。
- 送往 Vertex AI 的 payload 只含內容文字與規則特徵，**不含 user id、email 或任何識別資訊**。
- 審核紀錄（`moderation_records`）不存原文，只存判定結果與內容的 SHA-256 hash。
- Vertex AI 使用 `asia-east1`，專案層關閉 prompt 記錄與資料改善用途。

## 保存期限

| 資料 | 期限 |
|---|---|
| 帳號刪除 | 立即軟刪（頁面消失）→ 30 天後硬刪 |
| 活動資料（隊伍、申請、訊息） | 活動結束後依 `events.retention_days` 清除（預設 90 天，Cloud Scheduler 排程） |
| 審核紀錄 | 去識別化後 180 天 |
| Cloud Logging（含 IP） | 30 天輪替 |

## 當事人權利（個資法第 3 條）

- 個人資料頁一鍵匯出（JSON）
- 一鍵刪除帳號（流程中明確說明會退出目前隊伍）
- 蒐集告知（個資法第 8 條）直接呈現在註冊頁，不只藏在隱私權政策連結裡
